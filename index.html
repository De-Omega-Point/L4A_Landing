The problem

Small teams need useful digital tools, but paid access, download control and customer support often become messy fast.

1

Links get shared

Permanent public download links are easy to forward and hard to control.

2

Payments need proof

Operators need a clear record of who paid, what they bought and whether access is active.

The solution

Loyalty4All uses a simple access flow: customer chooses a plan, pays through PayPal, receives a serial number, then sees download and install guidance after confirmation.

For the MVP, the admin works locally in the browser. The code is structured so a backend can later verify PayPal webhooks, store records in Google Sheets and mint short-lived Google Drive links.

Designed to stay practical

  • Static frontend deployable to GitHub Pages
  • Backend-compatible payment placeholders
  • Local-first order admin prototype
  • Clear upgrade path for Google Apps Script

FAQ

Are Google Drive download links public?

No. The frontend is designed not to expose permanent public links. A backend should create short-lived links after payment and access checks.

Is this production payment verification?

No. The current static prototype includes clear TODOs for PayPal Orders API, webhooks, capture verification and subscription checks.

Can this run on GitHub Pages?

Yes. It uses static HTML, CSS and JavaScript.

Ready to test paid access?

Launch the static flow, validate demand, then connect PayPal webhooks and Google Apps Script when the process is proven.
